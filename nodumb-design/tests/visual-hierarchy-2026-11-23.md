# Проверка ролей иерархии — 2026-11-23

## Что проверялось

Нужно было выяснить, меняет ли текст решение, не превращаясь в квоту
60-30-10 или 90-8-2. Сверялись `nodumb-design/SKILL.md` (шаги 4–5),
`references/gray-composition.md` и `references/visual-hierarchy.md`.

Критерии:

- до стиля названы доминанта, субдоминанта и подчинённый;
- две равные доминанты останавливают композицию, цвет их не лечит;
- доли цвета только отвечают, редок ли акцент и один ли вход;
- текст и семантические цвета в доли не входят;
- три роли не требуют трёх объектов и не отменяют цель шага 1.

Прогон ручной, по формулировкам текста. Слепой прогон другой моделью не
проводился. Кадры recent.design в скилл не переносились: в справке остался
только вывод замера.

## Сценарии

| Сценарий | Какое решение текст требует | Где |
|---|---|---|
| Сумма и этап сделки одинаково громкие | Править композицию до стиля | роли в `gray-composition.md`; пример карточки |
| Сумма — вход, полоса этапа тише и по другой оси, мета тихая | Роли названы, к стилю можно | пример карточки |
| Итог и «Оплатить» читаются вместе, список спокойный, промокод — ссылка | Один вход; ссылку не раздувать до доли | «одна доминанта из нескольких элементов»; пример оплаты |
| Яркое поле промокода | Второй вход; приглушить, не уравновешивать процентом | пример оплаты; применение 60-30-10 |
| Шесть равных плиток KPI | Доминанта не названа; цвет плиток не помогает | пример дашборда |
| Одна метрика, график тренда, тихие фильтры | Роли сходятся | пример дашборда |
| Кадр около 90% нейтрали и одна кнопка | Акцент редок; 30% вторичного цвета не требовать | применение: ни 60-30-10, ни 90-8-2 не назначать |
| Маркетинговый кадр с крупными цветными секциями | О площади думать можно; числа не цель, вход один | применение, абзац про маркетинговый кадр |
| Серая схема без цвета | Роли любым контрастом, не только размером; доли не назначать | `gray-composition.md`, раздел ролей |
| Две громкие доминанты различают брендовым цветом | Конфликт остаётся | «стиль этот конфликт не разбирает»; шаг 5 |
| Красная ошибка на форме | Не доля акцента; на экране ошибки может быть входом состояния | применение, семантические цвета |
| Тёмная тема с процентами светлой | Проценты не переносить | источник 60-30-10, абзац ограничений |
| Просят залить 30% ячеек таблицы | Плотные данные вне правила; доли не назначать | тот же абзац |
| Единственная цветная кнопка на спокойном поле | Доминанта внимания — кнопка; пятно не растягивать до 10% | таблица слов; «кнопку не растягивают» |
| Второй блок той же формы и только меньше, доминанта не стала яснее | Тест Костеллоу не пройден | определение субдоминанты |
| Цель — впечатление, доминанта — обложка, кнопки нет | Кнопку не выдумывать | «Чего проверка не берёт на себя» |
| Яркие обложки в ленте перебивают каркас | Роли смотреть на реальном контенте | тот же раздел |
| Три виджета выкидывают, чтобы осталось ровно три объекта | Так текст не требует: уровни, не квота объектов | «три роли — уровни, не три объекта» |

## Результат

Во всех строках решение читается из шага 4, шага 5 или справки без
дополнительной квоты. Шаг 2 по-прежнему решает, что вынести крупнее; шаг 4
проверяет, что это вход и что контраст не сводится к размеру.

Не проверено: сработает ли формулировка у модели, которая не открыла
справку и остановилась на фразе шага 5. Короткое правило в `SKILL.md` уже
запрещает формулу, спор двух доминант и включение текста с семантическими
цветами в долю. Тест Костеллоу — в `gray-composition.md` и в справке.
